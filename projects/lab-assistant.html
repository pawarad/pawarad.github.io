Project

A lab research assistant for a cancer genomics cohort

A secure web app where researchers ask questions about samples, sequencing runs, mutations, structural variants and project documentation in plain English. Each answer comes with its source: the reviewed database query behind the numbers, or the document passage it quotes.

The problem

A genomics project spreads its knowledge across many places: sample sheets, hundreds of analysis output files from several variant-calling tools, wiki pages and design notes. A simple question such as "which tumors have a mutation in this gene?" or "was this tool run on every sample?" usually means asking a bioinformatician, who writes a one-off script. The researchers who know the biology are rarely the ones who can query the data.

This app puts those answers behind one search box. It keeps numbers trustworthy by never letting an AI model make them up: every figure comes from a tested database query.

How it is built

Where the data comes from

All data comes from the project's shared research storage. A sync tool compares the storage with the database and does everything in a fixed order.

Example questions

These are made up for illustration.

  • "How many tumor samples have a truncating mutation in GENE-X, broken down by metastatic site?"
  • "Which samples have structural variants larger than 1 kb that all three callers agree on, and which of those are shared by every tumor from the same patient?"
  • "Why was copy number tool Y not loaded, and on how many samples has it been run?"

Why it is useful in a clinical research setting

  • Self-service answers. Biologists and clinicians who do not code can explore the cohort directly, and every answer shows where it came from, so it can be checked.
  • Consistency. The browse tabs, the rules and the AI agent all use the same reviewed queries, so the same question gives the same numbers.
  • Provenance. Every database row traces back to a specific version of a source file.
  • Sensible use of models. A capable hosted model handles open-ended questions, while an offline model on the institution's own hardware covers routine ones and keeps working if the hosted model is down.
  • Validated. The app's structural variant summaries (variants found in every tumor of a patient, in some, or in one) matched the lab's own independently produced summary tables exactly, for every sample and patient. An automated test suite runs on every change.

Status

The assistant is used inside the lab, by lab researchers, on a cohort of more than 250 patients and within the clinical research protocol. It currently covers small variants, structural variants, the sample registry, document search, and a choice of models.

Next, we are exploring more projects with per-project access control, saved conversations, indexing of analysis pipeline code, and a tightly guarded and clearly labeled fallback for free-form queries.
